# Security reporting

Do not include credentials, tokens, real account names, private runtime profiles, database dumps, or unredacted logs in a public issue.

For a suspected vulnerability, use GitHub's private vulnerability reporting for the repository once enabled. If it is not enabled, contact the repository maintainers through a private channel listed on the project owner profile. Include a concise impact description and sanitized reproduction; do not publish exploit details before coordinating a fix.

KoreLab is local laboratory software and does not provide a security boundary for arbitrary untrusted scenarios or source trees. Run tests against disposable resources and review destructive plans before execution.
